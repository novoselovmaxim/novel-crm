# Mini-CRM для обзвона — Технический спек v2.0

> Май 2025 · Версия для передачи разработчику или AI-ассистенту

---

## 1. Цель проекта

Веб-приложение для командной работы с базой ~20 000 B2B-контактов. Основной сценарий — менеджер звонит потенциальному клиенту, цель звонка — назначить встречу. Три роли пользователей, общий дашборд, карточки компаний с историей звонков, управление задачами, Telegram-уведомления.

---

## 2. Пользователи и роли

| Роль | Кол-во | Права |
|------|--------|-------|
| **Админ** | 1 | Полный доступ. Импорт базы, назначение контактов, дашборд всей команды, редактирование любого контакта, управление пользователями, просмотр audit-лога. |
| **Руководитель** | 1 | Общий дашборд команды (как у Админа). Просмотр и фильтрация всех контактов. Участие во встречах. Не назначает задачи. |
| **Менеджер** | 1–2 | Видит только контакты, назначенные ему. Личный дашборд (задачи на сегодня). Меняет статус, пишет комментарий, логирует звонок, планирует следующий звонок. |

---

## 3. Архитектура и стек

### 3.1 База данных — PostgreSQL 16

Excel с 20 000 строк и 82 колонками медленный: каждый запрос перечитывает весь файл (~1–2 сек). PostgreSQL с индексами даёт фильтр за 5–10 мс.

Расширения: `pg_trgm` (полнотекстовый поиск по названию), `uuid-ossp`.

Индексы на таблице companies: `inn`, `region`, `call_status`, `assigned_to`, `next_call_date`, GIN-индекс на `name` для поиска.

### 3.2 Технологический стек

| Компонент | Решение | Обоснование |
|-----------|---------|-------------|
| База данных | PostgreSQL 16 | Быстрые индексированные запросы, надёжность, транзакции |
| Бэкенд | Python · FastAPI (async) | ~5 000 req/s на бюджетном VPS, автодокументация |
| ORM | SQLAlchemy 2.0 async + asyncpg | Нативный async, быстрее чем sync-драйверы |
| Аутентификация | JWT (access 15 мин + refresh 30 дней) + Telegram Login | httpOnly cookies, защита от XSS |
| Планировщик | APScheduler (в процессе FastAPI) | Утренние брифы, вечерние итоги, напоминания |
| TG-бот | python-telegram-bot | Уведомления, привязка аккаунтов |
| Фронтенд | React 18 + Vite · TypeScript · Tailwind CSS | Быстрая сборка, типизация |
| Таблица | TanStack Table v8 + виртуализация | Рендерит только видимые строки — 20 000 строк без тормозов |
| Стейт | Zustand + React Query | Кэш запросов, optimistic updates |
| Контейнеризация | Docker + Docker Compose | Один файл — один запуск |
| Обратный прокси | Nginx | SSL termination, статика фронта, proxy_pass |
| SSL | Let's Encrypt / Certbot | |
| Бэкапы | pg_dump по cron, ежедневно | 7 копий, хранить вне сервера |

## 4. Нормализация и миграция данных

### 4.1 Проблема исходного файла

82 колонки, из которых ~18 — дубли с суффиксами `__alt_merged`, `__alt_ved_ip`, `__alt_ved_jur`, `__alt_moscow`. Данные одного поля (название, регион, выручка) разбросаны по нескольким колонкам.

**Правило нормализации:** основная колонка → alt-колонка → пустая строка. Данные не теряются.

### 4.2 Итоговая схема таблицы `companies` (38 полей)

| Группа | Поля |
|--------|------|
| Идентификация | `id` (PK, UUID), `inn` (unique, indexed), `ogrn`, `kpp`, `org_form`, `reg_date` |
| Название | `name` — первое непустое: Компания / Наименование / Наименование клиента / ФИО |
| Местоположение | `region` (Регион регистрации → Регион), `address` (Адрес → Юр. адрес), `tax_office` |
| Контакты | `phone`, `email`, `website`, `linkedin` — alt-источники объединяются через ` \| ` |
| Руководство | `director`, `director_title`, `director_inn`, `fin_director`, `contact_person`, `citizenship` |
| Деятельность | `activity_main`, `activity_code`, `activity_other`, `niche`, `supply_subject` |
| Финансы | `revenue` (2022, Выручка RUB → Выручка), `profit`, `employees`, `capital`, `import_turnover`, `export_turnover` |
| Аналитика ВЭД | `import_confirmed`, `foreign_payments`, `arbitrage`, `licenses`, `registries`, `msp` |
| Прочее | `size`, `segment`, `priority`, `focus_link`, `source_orig`, `branches`, `comment_static` |
| CRM-поля | `call_status`, `next_call_date`, `assigned_to` (FK users), `call_count`, `last_called_at`, `days_since_contact`, `created_at`, `updated_at` |

### 4.3 Скрипт миграции `migrate.py`

- Читает Excel через pandas
- Нормализует колонки по правилам из 4.1
- Вставляет батчами по 500 строк (INSERT ... ON CONFLICT (inn) DO UPDATE)
- При повторном запуске — обновляет существующие записи по ИНН, не затирает CRM-поля
- Время выполнения: ~30 сек на 20 000 строк
- После импорта выводит отчёт: добавлено / обновлено / пропущено

## 5. Функциональность

### 5.1 Аутентификация

**Email + пароль:**
- JWT access token (15 мин) + refresh token (30 дней) в httpOnly cookies
- При истечении access — автоматическое обновление через refresh без logout
- Rate limiting: 5 неудачных попыток / 15 мин / IP → временная блокировка

**Telegram Login (дополнительный способ):**
- Пользователь один раз привязывает TG в настройках профиля
- После привязки — кнопка "Войти через Telegram" на странице логина
- Реализация: Telegram Login Widget (работает только на HTTPS с верифицированным доменом)
- Не заменяет email/пароль, а дополняет

**Создание пользователей:** только Админ через интерфейс.

### 5.2 Дашборд

#### Дашборд менеджера

- Карточки-метрики: задач на сегодня / просрочено / назначено встреч / звонков сделано сегодня
- Список контактов на сегодня (next_call_date = сегодня) — с названием, телефоном, последним комментарием
- Быстрые фильтры-пресеты: **Мои на сегодня** / **Просроченные** / **Перезвонить** / **Заинтересованные**
- Статистика за неделю: звонков / дозвонился / назначено встреч

#### Дашборд Админа и Руководителя

- Воронка команды: Новых → В работе → Заинтересован → Встреча назначена → Отказ (с цифрами и процентами)
- По каждому менеджеру: звонков сегодня / за неделю / конверсия в встречу
- Контакты без назначенного сотрудника (пул для распределения) — с кнопкой быстрого назначения
- Ближайшие встречи команды (следующие 7 дней)
- Контакты со статусом "Заинтересован" без follow-up больше 3 дней — красная зона

### 5.3 Таблица контактов

**Колонки в таблице** (всё остальное — в карточке):

| Колонка | Примечание |
|---------|------------|
| Компания | name, жирным |
| ИНН | моноширинный шрифт |
| Регион | + иконка UTC±X часового пояса |
| Деятельность | activity_main, с ellipsis |
| Выручка | форматировать: 3,4 млрд / 250 млн / 45 тыс |
| Телефон | кликабельный `tel:` |
| Сайт | иконка ↗, открывать в новой вкладке |
| Попыток | call_count — сколько раз звонили |
| Дней без контакта | days_since_contact — красный если >7 |
| Статус | цветной badge |
| Назначен | имя менеджера или — |
| Перезвонить | next_call_date, красный если просрочена |

**Колонки скрытые по умолчанию, включаются в настройках:** ОГРН, Орг. форма, Импорт/Экспорт, Сотрудники, Приоритет, Сегмент.

**Сортировка:** клик по заголовку колонки — asc/desc. По умолчанию: next_call_date asc.

**Quick-actions в строке** (появляются при hover):
- Иконка смены статуса (открывает dropdown прямо в таблице)
- Иконка "Назначить" (только Админ)
- Иконка телефона (открывает карточку сразу на форме звонка)

**Bulk-действия** (появляются при выборе чекбоксов):
- Назначить выбранные → менеджеру (только Админ)
- Экспорт выбранных в CSV
- Изменить статус выбранных

**Фильтры:**

| Фильтр | Тип |
|--------|-----|
| Поиск | Текст по name, inn, phone, email — debounce 300 мс |
| Регион | Текст с автодополнением (список из БД) |
| Статус | Мультиселект |
| Назначен | Select (список менеджеров) |
| Только с телефоном | Чекбокс |
| Выручка | Диапазон в млн ₽ |
| Перезвонить | До даты / просроченные / сегодня |
| Попыток звонка | Диапазон (например: 0 / 1–3 / 3+) |

Все фильтры работают через PostgreSQL-запросы с индексами — применение < 100 мс. Состояние фильтров сохраняется в URL (можно поделиться ссылкой с уже выставленными фильтрами).

**Быстрые пресеты** (кнопки над таблицей):
- Мои на сегодня
- Просроченные
- Без назначенного
- Заинтересованные
- Новые (без статуса)

### 5.4 Карточка компании

Открывается в правой панели (slide-in, 480px) при клике на строку. Таблица остаётся видна. На узком экране — полноэкранно.

#### Верхняя зона (always visible, sticky)

- Название компании (крупно), ИНН, ОГРН, орг. форма
- **Блок времени клиента:** живые часы в часовом поясе региона + статус (🟢 рабочее 9–18 / 🟡 граница 8–9 и 18–20 / 🔴 нерабочее). Моё текущее время рядом для сравнения.
- Телефон — кликабельный `tel:`, все номера
- Email, сайт
- Счётчик: попыток звонка / последний контакт X дней назад
- **Постоянная заметка** — отдельное поле, не история звонков ("Иван принимает решения, не звонить до 10:00")

#### Форма звонка (sticky, под верхней зоной)

- Кнопки статуса одним кликом (6 штук — см. раздел 5.5)
- Текстовое поле комментария к этому звонку (автосохранение через 1 сек)
- Дата следующего звонка (datepicker с быстрыми кнопками: +1 день / +3 дня / +неделя)
- Результат встречи (появляется если статус = "Встреча назначена"): textarea для итогов
- Кнопка "Сохранить звонок" → создаёт запись в call_log
- Кнопка "Добавить в Google Calendar" (появляется при выборе даты)
- Кнопка "Добавить в Apple Calendar" (.ics файл, появляется при выборе даты)
- Назначить менеджера (select, только для Админа)

#### Секции с данными (аккордеоны, раскрываются по клику)

- Контакты — телефон, email, сайт, LinkedIn, представитель/ЛПР
- Реквизиты — ИНН, ОГРН, КПП, орг. форма, дата регистрации, регион, адрес, МСП, налоговый орган
- Руководство — ФИО, должность, ИНН руководителя, фин. директор, гражданство
- Деятельность — ОКВЭД, код, ниша, предмет поставки
- Финансы — выручка, прибыль, сотрудники, капитал, импорт/экспорт оборот, арбитраж
- Прочее — реестры, лицензии, сегмент, приоритет, карточка в Фокусе, источник
- История звонков — хронологический лог

#### Редактирование полей

- Клик на любое поле → inline-редактирование
- При сохранении — диалог подтверждения "Сохранить изменения?"
- Все правки пишутся в `audit_log` (кто, когда, что изменил, старое и новое значение)

#### История звонков

Хронологически, новые сверху. Каждая запись: дата+время, статус (badge), комментарий, имя менеджера. Первые 5 записей видны сразу, остальные — "показать все".

### 5.5 Статусы контакта

| Статус | Цвет | Описание |
|--------|------|----------|
| Новый | Серый | Контакт не обрабатывался |
| Не дозвонился | Оранжевый | Звонил, трубку не взяли |
| Не отвечает | Красный | Несколько попыток — не берёт |
| Перезвонить | Синий | Попросили перезвонить позже |
| В работе | Жёлтый | Идёт диалог |
| Заинтересован | Зелёный | Проявил интерес, продолжаем |
| Встреча назначена | Фиолетовый | Договорились о встрече |
| Отказ | Тёмно-серый | Отказался, не интересно |

### 5.6 Интеграция с календарями

Без OAuth, без синхронизации — простые ссылки:

**Google Calendar:** при выборе даты встречи в карточке → кнопка формирует URL:
```
https://calendar.google.com/calendar/render?action=TEMPLATE
  &text=Встреча: {company_name}
  &dates={datetime_start}/{datetime_end}
  &details={phone} | {comment}
```
Открывается в новой вкладке, пользователь нажимает "Сохранить".

**Apple Calendar / Outlook:** кнопка генерирует `.ics`-файл и скачивает его. Стандартный формат, открывается любым календарным приложением.

Полная двусторонняя синхронизация — не нужна на текущем этапе.

### 5.7 Telegram-уведомления

**Привязка аккаунта:**
1. Пользователь в профиле нажимает "Привязать Telegram"
2. Получает ссылку на бота с одноразовым токеном
3. Пишет боту `/start {token}` — бот сохраняет `chat_id`
4. Готово. Можно отвязать в настройках.

**Расписание уведомлений (APScheduler):**

| Время | Кому | Содержание |
|-------|------|------------|
| 9:00 МСК | Каждому менеджеру | Утренний бриф: задач на сегодня N, перезвонить M. Список компаний с телефонами. |
| 9:00 МСК | Админ + Руководитель | Сводка команды: кто что делает, сколько задач у каждого. |
| За 60 мин до встречи | Менеджеру + Руководителю | "Встреча через час: {company_name}, {phone}" |
| За 15 мин до встречи | Менеджеру | "Встреча через 15 минут: {company_name}" |
| 18:00 МСК | Каждому менеджеру | Итог дня: звонков сделано / дозвонился / назначено встреч. Что перенесено на завтра. |
| 18:00 МСК | Админ + Руководитель | Командный итог дня по каждому менеджеру. |

**Дополнительные триггерные уведомления:**
- Менеджеру назначили новые контакты → уведомление сразу
- Контакт перешёл в статус "Встреча назначена" → уведомление Руководителю
- Заинтересованный контакт без follow-up 3+ дня → напоминание менеджеру

Уведомления можно отключить индивидуально в профиле.

### 5.8 Мобильная версия

Полная таблица на мобиле не нужна — неудобно. Нужен отдельный упрощённый вид для менеджера.

**Мобильный вид (breakpoint < 768px):**
- Вместо таблицы — карточки-карусели: название, телефон, статус
- Кнопки статуса крупные (достаточный tap target)
- Поле комментария с автосохранением
- Свайп влево → следующий контакт из списка на сегодня
- Фильтры скрыты за кнопкой, открываются в bottom sheet

Реализуется в том же React через media query — отдельного приложения не нужно.

**Что недоступно на мобиле:** admin-функции, bulk-действия, дашборд команды.

### 5.9 Добавление контакта вручную

Форма создания нового контакта (только Админ и Руководитель). Обязательные поля: название, ИНН. Остальное — опционально. При сохранении — проверка на дубль по ИНН.

### 5.10 Экспорт

- Экспорт текущей выборки (с учётом фильтров) в CSV
- Для менеджера — только его контакты
- Для Админа — любая выборка
- Максимум 5 000 строк за раз

## 7. API эндпоинты

### Аутентификация
```
POST   /auth/login           email + пароль → JWT tokens
POST   /auth/telegram        TG Login данные → JWT tokens
POST   /auth/refresh         Обновить access token
POST   /auth/logout          Инвалидировать refresh token
GET    /auth/tg-link         Сгенерировать одноразовый токен для привязки TG
POST   /auth/tg-bind         Привязать TG chat_id по токену (вызывает бот)
```

### Пользователи (только Админ)
```
GET    /users                Список пользователей
POST   /users                Создать пользователя
PATCH  /users/{id}           Обновить (роль, имя, is_active)
DELETE /users/{id}           Деактивировать
```

### Контакты
```
GET    /companies            Список с фильтрами, пагинацией, сортировкой
GET    /companies/{id}       Карточка — все поля
POST   /companies            Создать вручную (Админ + Руководитель)
PATCH  /companies/{id}       Обновить поле(я) + запись в audit_log
DELETE /companies/{id}       Мягкое удаление (is_deleted = true, Админ)
POST   /companies/{id}/call  Сохранить звонок → call_log + обновить статус + call_count
```

## 8. Безопасность

- **Пароли:** bcrypt, cost factor 12
- **JWT:** access в памяти JS, refresh в httpOnly SameSite=Strict cookie → защита от XSS и CSRF
- **Rate limiting:** 5 попыток логина / 15 мин / IP — через slowapi или nginx limit_req
- **Авторизация:** каждый запрос проверяет роль. Менеджер получает только `assigned_to = user.id`. ORM-уровень, не только фронт.
- **CORS:** только домен приложения
- **Nginx:** заголовки X-Frame-Options: DENY, X-Content-Type-Options: nosniff, HSTS, CSP
- **PostgreSQL:** отдельный пользователь с правами только на нужные таблицы (не superuser)
- **Переменные окружения:** DB_URL, JWT_SECRET, TG_BOT_TOKEN — только в `.env`, не в коде, `.env` в `.gitignore`
- **Бэкапы:** pg_dump ежедневно по cron, хранить 7 копий. Хранить вне сервера (SFTP / Backblaze B2 / S3-совместимое)
- **TG Webhook:** верификация подписи от Telegram через HMAC-SHA256
- **Audit log:** все изменения данных пишутся с user_id, timestamp, старым и новым значением

## 9. Интерфейс и UX

**Тема:** тёмная. Фон `#0F1117`, поверхности `#1A1D27` / `#222536`, акцент `#4F6EF7`, текст `#E2E8F0`, muted `#8892A4`.

**Шрифт:** Inter (подключить через Google Fonts или self-host) или системный стек.

**Таблица:** фиксированные заголовки, виртуальный скролл (только видимые строки в DOM), высота строки 40px, hover-подсветка, active-подсветка выбранной строки.

**Карточка:** slide-in справа 480px. На экранах >1280px таблица и карточка видны одновременно. На <1280px — карточка перекрывает таблицу, крестик для закрытия.

**Статусы:** цветные badge-пилюли, однозначные цвета из дизайн-системы.

**Время клиента:** живые часы в карточке + цвет фона блока (тёмно-зелёный / тёмно-оранжевый / тёмно-красный).

**Optimistic updates:** UI меняется мгновенно, запрос идёт в фоне, при ошибке — откат и уведомление.

**Toast-уведомления:** снизу справа, 2.5 сек, успех/ошибка/инфо.

**Состояние фильтров в URL:** `?region=Москва&status=interested` — можно поделиться ссылкой.

**Пустые состояния:** если ничего не найдено — иллюстрация + текст, не просто пустая таблица.

**Мобильный вид** (< 768px): карточки вместо таблицы, bottom sheet для фильтров, крупные кнопки статусов, свайп между контактами.

## 10. Деплой на VPS

### Минимальные требования
- 2 vCPU, 4 GB RAM, 30 GB SSD
- Ubuntu 22.04 LTS
- Docker + Docker Compose v2

### Структура Docker Compose

```yaml
services:
  postgres:
    image: postgres:16
    volumes: [pgdata:/var/lib/postgresql/data]
    env_file: .env

  backend:
    build: ./backend
    env_file: .env
    depends_on: [postgres]

  frontend:
    build: ./frontend
    # собирает React, отдаёт через nginx внутри контейнера

volumes:
  pgdata:
```

Внешний nginx на хосте проксирует: `domain.com` → frontend, `domain.com/api` → backend.

### Порядок первого запуска

```bash
git clone / scp на сервер
cp .env.example .env && nano .env  # заполнить DB, JWT_SECRET, TG_BOT_TOKEN, домен
docker compose up -d
docker compose exec backend python migrate.py  # импорт Excel
docker compose exec backend python create_admin.py  # первый пользователь
certbot --nginx -d domain.com  # SSL
```

### Бэкапы (cron на хосте)

```bash
# /etc/cron.d/crm-backup
0 3 * * * docker compose exec postgres pg_dump -U $DB_USER $DB_NAME | gzip > /backups/crm_$(date +\%Y\%m\%d).sql.gz
# Удалять старше 7 дней + копировать на внешнее хранилище
```
